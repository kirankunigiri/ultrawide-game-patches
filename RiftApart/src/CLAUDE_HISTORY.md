## What was built

The work moved from a feasibility discussion to a Python external overlay. A transparent, click-through, always-on-top Tk window draws an extracted top-down planet texture, the player marker, collectible/objective markers and explored-area shading. It reads the running process through read-only `pymem`; it does not inject code into the game. ALERT extracted Sargasso's 2048×2048 map texture. The art was aligned to game coordinates using the game's bounds; the other planets still lack extracted/aligned map art. The final UI state described in the transcript is a square minimap and a ` key toggle for fullscreen map, both at 70% opacity, with 190 world units center-to-edge in the minimap and 700 world units fullscreen height. The user had initially asked for 60% fullscreen opacity; later changes set both views to 70%. The game's own collectible icon art was extracted for 19 icon types.

## Reverse-engineering findings and useful addresses

Addresses below are for the inspected 3.630.1.0 executable. The image base used in static analysis was 0x140000000; prefer RVAs over absolute addresses when referring to code/data because runtime addresses can be rebased.

- The pause-map fog builder was identified as `GUI2::PauseMenuElementMapPage::InitMapTextures`, at 0x141A55850 (RVA 0x1A55850). Static xrefs include the `FogOfWarSystem::m_VisitedFogCells` name. Its cell test reads a bit from the visited buffer. The related live class's RTTI/vtable was found at RVA 0x462B450.
- The fog map table is read at `exe + 0x580FC08`. Its fields are keys pointer at +0, records pointer at +8, capacity at +0x14, and record stride at +0x20. Each record has width at +0x78, height at +0x7C, and a self-relative-or-absolute visited-bit-buffer pointer at +0x80. Cell identity is map ID plus row and column; the buffer stores one visited bit per cell (roughly two world units per cell). The scratchpad reader is `fogread.py`.
- Two relevant helpers surfaced in disassembly at 0x1415AD3F0 (hash-table lookup) and 0x1415B19D0 (buffer getter). The map icon UI uses `MapIconData` records of 0xE8 bytes: image path at +4, visible/complete flags at +0x84/+0x85, arrow rotation at +0xC8, rotation at +0xCC, ID at +0xD8, and displayed x/y at +0xDC. The initial live array was at 0x1ACE96E7168, but that heap address is temporary. Later code re-finds it using the `MapIconPlayer.texture` record signature, type 2, and the empty preceding slot.
- The exact Sargasso map bounds read from the fog/map data are X −192…920 and Z −728…384 (`map_bounds_sargasso.json`, source recorded as fog record MapMin/MapMax). This replaced a screenshot fit that had been off by up to four world units.
- Player position is not a single stable heap address. Early scanning found many replicated `(x,y,z)` copies, then a one-snapshot auto-reacquire chose unreliable/transient copies. The final `heroread.py` resolves multiple executable-static-root pointer chains from `chains_ok.json` and `facing_chains.json`; the positions from the chains are clustered (within 1 unit), and at least three agreeing readings are required. Examples of validated X/Z roots include `exe+0x6768310 -> +0x10`, `exe+0x64FEFC0 -> +0x278 -> +0x268`, and `exe+0x64FF630 -> +0x2F8 -> +0x268`; the JSON has the full candidate set. Heading comes from the forward axis in row 2 of the hero root transform. Representative facing chains include `exe+0x68FB850 -> +0x1F8 -> +0x30` and `exe+0x600FA80 -> +0x50`. `hero_xz_filtered()` rejects jumps over 3 units unless the new reading repeats for three consecutive samples. These are game-version-specific roots, not durable public APIs.

## Desync and bug history

- **Stale player reads:** after respawn/load/area change, fixed heap addresses stopped pointing to Rivet and yielded near-zero values, placing the player at world origin. A heuristic that selected a large cluster of position copies then teleported across the map because some copies were temporary buffers reused for NPCs. The fix was multi-movement-validated pointer chains rooted in executable globals, plus agreement clustering and a three-read jump filter.
- **Rare position jumps remain a known risk:** the jump filter was added after diagnostics showed occasional inconsistent chain readings. The final transcript says jumps occurred in about one in four benchmark runs before filtering, and filtering had not yet been re-tested after the change.
- **Duplicate collectible/robot markers:** each pan/zoom capture treated map-screen coordinates as default-zoom coordinates and kept adding transformed copies. Capturing once at map-open, before pan/zoom, measuring relative to the player's own icon, and replacing that map's old capture fixed the identified cause.
- **Map outline/world mismatch:** calibration used a screenshot taken while the map was panned/possibly zoomed. Fog texture alignment did not prove world alignment. Exact map bounds from the game's map/fog record corrected the transform.
- **Fog desync:** an earlier local exploration trail could not include prior progress and would diverge from the pause map. Static analysis found the game's own visited-cell grid; the overlay now reads the same map table/grid/map ID every second, including previously explored areas and other maps already in memory.
- **Heading flicker:** some frames had no trustworthy angle, so the marker reverted to a dot. Final behavior preserves the last valid heading; pause-map player icon rotation calibrates the angle offset.
- **Toggle misses:** polling could miss short ` presses, particularly while moving. The implementation was changed to a low-level keyboard hook (`VK_OEM_3`) gated on the game being focused.

## Validation and current limits

Movement scans and later pointer-chain checks compared readings against the large set of live hero-position copies while driving in several directions. The transcript reports position and heading reads in about 1 ms, and balanced movement benchmarks ended within about two units of their start. Map-open icon capture, extracted art, map outline, and UI states were checked with offline renders and screenshots. Python compilation was run after several changes; the script was relaunched.

At the last transcript update, some requested behavior still needed live confirmation: the ` toggle while moving, the new rare-jump filter, fullscreen drawing beyond the map edge, and visual comparison of fog shading with the actual pause map. Fog styling was checked in an offline test render. Only Sargasso had map art, so other planets had no background yet. Map markers refresh when the pause map is opened, so collection-state changes can be stale until the next open. The earlier claim that the fullscreen view is 60% opacity was superseded by the later 70% setting.

## User preferences captured

The user wanted a collectible-focused map, exact game marker art, prior exploration synchronized with the game, a direction arrow that never drops back to a dot, and a quick ` toggle for a larger fullscreen map. They preferred automation that works from scripts without having to operate Cheat Engine or enter data in an app. They were comfortable having the already-open game read for this work and supplying simple movement tests. They praised the prototype, then reported the duplicate markers and world/map outline mismatch, and later the player teleport/desync. They asked whether the fullscreen view could be toggled quickly and preferred exploring past progress to match the real map.
